                     INTER-SERVICE COMMUNICATION

If hello-service needs to call car-rental-service:

  ┌─────────────────────────────────────────────────────────────────────┐
  │  HelloService needs car data                                        │
  │                                                                      │
  │  URL: http://car-rental-service:8080/cars                          │
  │       (uses service name, not localhost)                           │
  │                                                                      │
  │  Docker Network Resolution:                                        │
  │  car-rental-service → resolves to container IP                    │
  │  (Docker's embedded DNS handles this)                             │
  │                                                                      │
  │  Result: Services can communicate by service name                 │
  │          within the Docker network                                │
  └─────────────────────────────────────────────────────────────────────┘

KEY CONCEPTS ILLUSTRATED:

1. MICROSERVICES
   ├─ Separation of concerns (each service has one job)
   ├─ Independent deployment
   ├─ Technology agnostic (could use different languages)
   └─ Communication via REST APIs

2. CONTAINERIZATION
   ├─ Multi-stage builds (efficient images)
   ├─ Container isolation
   ├─ Environment consistency
   └─ Easy deployment

3. ORCHESTRATION
   ├─ Service definition (docker-compose)
   ├─ Network management (rental-network)
   ├─ Port mapping
   └─ Service discovery (by name)

4. REST ARCHITECTURE
   ├─ HTTP methods (GET, PUT)
   ├─ Resource endpoints (/cars)
   ├─ Status codes (200, 404, 409)
   └─ JSON payloads

                      HOW IT ALL CONNECTS

Developer's Machine
    │
    ├─ $ git clone <project>
    ├─ $ cd rental
    ├─ $ ./start.sh up
    │
    └─ Docker Compose starts:
        ├─ Reads docker-compose.yml
        ├─ Creates rental-network
        ├─ Builds car-rental-service:latest
        ├─ Builds hello-service:latest
        ├─ Starts car-rental-service container
        ├─ Starts hello-service container
        ├─ Maps ports (8080, 8081)
        │
        └─ Services are now RUNNING
            ├─ Car-Rental API accessible at http://localhost:8080
            ├─ Hello Service accessible at http://localhost:8081
            └─ Both services can talk to each other
                via Docker network (rental-network)
